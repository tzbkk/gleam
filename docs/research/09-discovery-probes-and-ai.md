## 1. 五层发现管道（提案；顺序即优先级，不是配额）

1. **离线解析**：本地确定性来源（UDD 快照、`debian/watch`、DEP-12、upload history、VCS 元数据、copyright Source 字段）。零网络，完全可复现。
2. **已知端点探针**：对已登记或经候选审核的应用层端点做 HTTPS、HTTPS Git、Atom/RSS、发布目录、平台 API 探测；保留完整重定向链，限速，记录原始响应引用。
3. **结构化外部查询 + 周期性重发现**：Repology、Anitya、SWH 等具名来源；并且即使旧站点仍返回 200，也要周期性重发现。wizznic 实证：对着尸体产地认证的 "up to date" 无法自我纠错，只有外部重扫能救。
4. **预算内一般搜索**：仅在身份未决、旧端点失效或搬迁可疑时触发；输出候选，不直接确认绑定。
5. **可选 AI 假设 + 人工/规则复核**：AI 整理证据、摘取原文、提出关系候选；输出必须引用观测证据 ID，并进入审核流程。

不做：原始 TCP/UDP 端口扫描（06 §3 已排除）。

## 2. "remote ports" 歧义澄清（记录存档）

先前记录里出现过 "remote ports" 字样，语义有歧义：可能指远端搜索或模型 API，也可能被读成原始端口扫描。

本页存档澄清：**不假定用户意图是扫端口。** 普通公共应用层端点（网页、git 协议、feed、平台 API）是首选且有用的观测面；原始端口清扫没有必要，且与框架边界冲突。本页不主张"这些端点足以覆盖全部观测需求"：够不够取决于目标信道，证据不足时按 §1 分层升级。任何实现读旧记录时，以框架边界为准，不按旧措辞扩展。

## 3. 探针误差与信号质量（实测教训清单）

- **探针错误 = 未知，不是死亡判决。** 超时、5xx、TLS 失败一律落 unknown，不得推出否定性主张（simulavr 的 savannah git web 超时，仓库状态只能标 UNKNOWN）。
- **git refs 变化本身不带时间戳与作者信息。** refs 事件必须从别的信道（feed 条目、commit 对象）取时间和归属。spacefm 的 `pushed_at=2024` 配零 commit 实证：仓库元数据事件会冒充活动。
- **TLS 证书续期是自动化运维，不是软件活动。** 不得作为活动信号。
- **HEAD/ETag/mtime 只是提示。** utf8gen 的目录 mtime 被服务器迁移刷新；wiggle 的镜像 tag 日期系 2020 年回填。单文件页面的 Last-Modified 可能是唯一存在的信号（key-chord.el），但仍要标弱信号、归属未知。
- **feed 必须绑定到正确项目与路径。** emacs-helm-ag 重定向进 emacsattic org 后 feed 仍 200；该案例实为同一项目的看护人转移，重定向本身不一定指向错误项目。要点是核对重定向链与归属、确认 feed 确实属于目标实体，而不是把"重定向"一律当错误。
- **网站上的 pkg-name 正则命中不是身份证明。** wvware 冒名 org 正是按名字搜索找到的错误活体；身份核对要查作者、首 commit、README（F 批修正 5）。
- **密钥连续性依赖可信密钥锚。** 签名发布只能证明"同一把钥匙的持有者发声了"；钥匙锚本身要有出处。密钥被替换时，须人工核查是泄露/吊销还是正常轮换，并核对人类可读的出处记录。镜像上的重签或回填签名不推翻已用原钥验证过的原件；镜像自身的拷贝要另行验证。
- **多个发行版可共享同一份拷贝证据。** 跨发行版佐证（xtrs 式）是强证据，但先排除同源复制：各家携带同一 Debian tarball 不构成独立信号（05 §7 Q6 待定规则）。

## 4. 安全与权限边界（继承 06 §3，具体化）

- **SSRF 防护**：每一跳重定向目标都解析并按公网地址校验，拒绝内网与保留段；配合出口控制（允许网段、代理出口），scheme 白名单（https、git+https 等）。
- **Git 只读隔离**：clone/fetch 在沙箱内执行，不跑 hooks、不构建、不执行任何仓库内代码。
- **解析器防护**：XML 一律禁外部实体（XXE）；响应体大小上限、请求速率上限、超时上限（压测经验：`--max-time 15`、SWH 1 req/s、Repology 1.2s 间隔）。
- **只做授权的只读访问，不绕过任何访问控制**：robots 与平台条款遵守；遇登录墙默认不抓取，仅在获得授权时以只读方式访问；拿不到就记为 unknown。

## 5. AI 分诊（提案；阈值与模型选型未定）

- **无身份变更权限**：AI 对已确认的身份记录没有变更权限；可以有一个提案存储路径（候选关系、证据清单、摘要进入待审区），不直接落实体、不做合并。
- **结构化输出**：引用证据 ID、逐字引文、模型名称与版本、prompt 哈希、失败与弃权记录。弃权是合法输出，比编造好。
- **自评分不是校准概率。** 模型自报的分数不得当概率用，不得据此设任意阈值门（例如 0.35-0.85 区间的固定门槛），也不得把"14B 模型足够"之类的建议写成规范。先前非正式记录中有此类说法，一律按未验证存档、不采纳。
- **提示注入防护**：AI 输入中混入的网页内容按不可信数据对待（OWASP LLM 防护清单见 §6）；AI 建议永远过人工或规则复核。
- **人工复核先行**：先复核既有调查结果（2026-10-29 的 81 包压测）建立 gold set，再评估 AI 分诊的错误合并率与候选召回。
- **消融实验设计（提案）**：四臂对比 local / local+probe / +search / +AI，度量：错误合并数、候选召回、人工复核工作量、成本与延迟。这是评估 AI 增益的正确姿势，先于任何模型或阈值决定。

## 6. 观测结果语义（示意词表，非已接受规范）

探针落库时的 outcome 语义建议与状态解耦，先用一组中性词（以下字段为示意，未定稿）：

| outcome | 含义 | 可推出的主张 |
|---|---|---|
| `OK` | 传输层成功（任何成功状态码，200 只是其中之一） | 一条传输成功的观测；仅此而已 |
| `MOVED` | 3xx，且重定向终点已核验 | 位置迁移候选；身份归属另核 |
| `REPRESENTATION_CHANGED` | 表示层哈希 / ETag 相对上次变化 | 表示变化候选；ETag 变化单独不等于语义内容变化，归属未知 |
| `NOT_MODIFIED` | 304 响应，或 200 且内容指纹未变 | 一个"此处仍原样"的观测 |
| `TRANSPORT_ERROR` | 超时、5xx、TLS 失败等传输/解析失败 | 无主张；下轮重试或换信道 |
| `ABSTAIN` | 方案性放弃（预算、权限、robots） | 无主张；记录原因 |

三类信息分开记录：传输状态/错误、表示层哈希变化、经解释的活动信号。三者互不推导：304 是"未修改"的正常响应，不是错误；哈希变化要经解释才成为活动候选。

这套词表的价值是把"探针错误"从"上游死了"的误读里拆出来：传输错误只产生重试义务，不产生任何状态结论。wizznic（假覆盖）、net-dns-fingerprint（NULL 冒充包属性）、simulavr（UNKNOWN 被当事实）三类翻车都源于把 outcome 直接读成状态；注意 NULL / 缺记录只证明"没有已记录的结果"，不证明"管道从未运行"。

### 预算与速率的历史参考（先前 agent 自报，无集中请求日志）

- 压测六批共享单一出口 IP，各批自报 GH `api.github.com` 合计约 4 次调用；多批结论依赖 atom feed、SF JSON/RSS、SWH（约 1 req/s）、目录 mtime、Repology（约 1.2s 间隔）。这些数字是历史实测快照，不是当前 API 政策，也不是本项目的集中统计。
- 注意：公开 feed 与公开端点并非无限免计量，仍受平台速率限制与条款约束；"自报未触限"不等于"成本充足"已获证明，本页不作此推断。长期运行的速率与封禁风险未积累数据。
