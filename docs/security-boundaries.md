# Security boundaries

- HTTP(S) only. URLs with embedded credentials and malformed URLs are rejected; every redirect hop is fully re-validated.
- SSRF defenses: DNS must resolve to a public unicast address (loopback, private, link-local, reserved, and multicast ranges are refused, including unwrapped IPv4-mapped IPv6); the connection is then pinned to that resolved IP while TLS keeps checking the original hostname, which defeats DNS rebinding. Proxy environment variables are ignored by the public fetcher.
- Caps are configurable via `.env` or flags: byte cap (default 300000), per-fetch timeout (default 15s), redirect cap (default 3), the shared HTTP request budget (default 52), and a same-host minimum interval (default 1s).
- robots.txt is decided per hop before every GET, including redirect targets. Disallow rules, 401/403/5xx answers, truncated robots bodies, and fetch failures cause an abstention (the outcome stays unknown and is never read as "no results" or "project dead"); 404/410 means unrestricted. Host-level failures (DNS, refused connections, unsafe addresses) are reported as transport errors, not robots abstentions.
- One operator-owned exemption exists: `--robots-exempt-file` (default `robots-exempt.txt` in the working directory) lists bare hostnames, validated loudly at startup (a bad line is a usage error, exit 2, before any run is created). Listed hosts skip the robots.txt pre-fetch entirely — justified only where a site's own API terms authorize programmatic access despite a blanket robots disallow (repology.org) — while every other safety layer (SSRF guards, DNS pinning, byte caps, rate limits, timeouts) still applies, and each exempted fetch is marked `robots: "exempt"` in its audit record so exempt never looks identical to robots-allowed. The active exemption set is disclosed in every fetch policy record. A second, tool-intrinsic exemption exists only inside the repology client: its fetcher exempts the host of its configured API base (the same API-terms rationale, scoped to the tool's own fetcher). It never leaks into the investigation's main fetcher — manual `fetch_url` keeps exactly the operator-file exemption set, and every repology fetch still discloses its own effective `robots_exempt` list in its audit record.
- No autonomous crawling exists. Only explicit model tool calls fetch anything, each one through the full safety layer above. `search_web` uses a separate code path for a trusted local SearXNG instance and never follows redirects.
- Trusted endpoints are operator-configured and never derived from fetched data: the model endpoint (`--model-base`), the local SearXNG instance (`--search-base`), and the GitHub API base (`--github-api-base`, whose requests still traverse the full public-fetcher safety layer). The model cannot point tools at local or internal addresses.
- Driver and environment discipline: the UDD connection uses the pure-Python pg8000 driver and inherits zero environment: no `PG*` variables are passed on, no libpq configuration files are consulted, and no shell is involved. Every query runs in a read-only transaction under a server-side statement timeout and a per-statement deadline; the driver prefers TLS and falls back to plaintext only when the server refuses TLS. The model client connects directly by default; a proxy is used only when explicitly set via `GLEAM_MODEL_PROXY`. An optional `GLEAM_MODEL_API_KEY` travels only as an `Authorization: Bearer` header to the configured model endpoint and is never written to audit records, run directories, or Results.
